Run from python04/ex3 to reproduce the PDF's four cases:
  chmod 000 denied_fragment.txt
  python3 ft_vault_security.py
  chmod 600 denied_fragment.txt

Expected results: False (missing), False (permission denied), True (read),
True (write). The local filenames differ from the PDF's example paths.

The demonstration reads does_not_exist.txt, denied_fragment.txt, and
ancient_fragment.txt, then creates or replaces recovered_fragment.txt.
The paths are relative to your terminal working directory.

The denied file is normally readable so Git can add it. Without chmod 000,
the second call correctly returns True because the file is accessible.
Restore readability before staging it. Git does not preserve mode 000
read/write permissions; repeat chmod 000 locally after a clone.
Root/administrator processes may bypass these permissions.
